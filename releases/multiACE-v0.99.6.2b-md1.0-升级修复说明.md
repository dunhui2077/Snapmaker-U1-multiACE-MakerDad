# multiACE v0.99.6.2b-md1.0 升级修复说明

## 基础版本

本版本以 `multiace-0.99.6.2b-paxx-mod` 的 PAXX 固件 overlay 为基础，
保留其启动脚本、Web 安装方式、固件配置注入和预装 Python 依赖，并迁移
`multiACE-0.99.6.2b-md0.9` 的全部功能与修复。

## 已迁移功能

- ACE / MCU 与 ACE2 多设备通讯稳定性、握手超时重连和辅助送料修复。
- 流量校准期间保持 ACE2 辅助送料。
- 完整的手动烘干与自动烘干界面、参数和任务逻辑。
- 打印温度保护、超温等待提示、打印结束后恢复被保护暂停的烘干任务。
- 打印正常结束后全部退料、断料后释放进料控制、喷嘴实际出料确认。
- 材料来源自动修复、手动修复和测试用断开来源链接。
- 耗材信息同步到 Klipper、AFC 和机器物理屏幕。
- Fluidd 虚拟面板多 ACE 卡片同步：切换卡片时执行与完整控制台相同的
  `ACE_SWITCH` 路径；再次点击当前 ACE 仅刷新材料映射，不执行进退料。
- 浏览器端大 G-code 预检、中文弹窗/错误/悬停提示完整化，以及英文和德文
  键名显示修复。

## 发行文件

- `multiACE-v0.99.6.2b-md1.0.zip`：完整源码和 PAXX overlay。
- `multiace-v0.99.6.2b-paxx-mod-md1.0.tar.gz`：可直接放入 PAXX 工程
  `overlays/firmware-extended/` 的 `40-feature-multiace` overlay。

升级或刷写前请备份现有打印机配置。首次使用时重启 Klipper，并检查 ACE
数量、工具头来源、允许打印温度和打印结束退料设置。

## 1.0 同步修复：Web 全部退料

- 修复 Web 前端“退出所有材料”完成后保存工具头材料来源时可能触发
  `Internal error on command:"SAVE_VARIABLE"` 并使 Klipper SHUTDOWN 的问题。
- 根因是 G-code 参数解析会剥离映射数据的字符串引号；`save_variables.py` 现在
  校验并接受 `b64:` 格式的 UTF-8/Base64 来源映射，退料后可正常清空并保存映射。
- 同时捕获 `SyntaxError`；即使未来收到无效保存值，也只会返回普通命令错误，
  不会关闭 Klipper。

## 本次补充

- Fluidd 虚拟面板的 ACE 卡片改为直接调用后端同步宏，避免 iframe 队列被
  Fluidd 暂停或回收后未执行。切换 ACE 时同步完整 Web、Klipper AFC 和
  机器屏幕；点击当前 ACE 仅重新刷新耗材映射。
- ACE2 手动烘干面板在“停止”后增加排湿口“打开/关闭”按钮。按钮使用阀门
  接口同时控制两个排湿阀，并以呼吸动画显示当前开闭状态。
- 排湿口控制已与手动烘干控制合并为同一行，并紧跟手动烘干开始/停止按钮；
  手动烘干、自动烘干和排湿口的开始/打开按钮在生效时统一显示“工作/已打开”
  并使用橘色呼吸提示，停止/关闭状态使用一致的停止文案和状态动画。
- 版本标识统一为 `v0.99.6.2b-md1.0`，发行文件不再叠加重复的版本前缀或后缀。
- 修正 Web/Fluidd 版本显示：不再将内部 `md1.0` 构建标记拼接到用户版本号，
  同时移除多语言模板重复添加的 `v` 前缀，最终显示为
  `v0.99.6.2b-md1.0`。
- 烘干与排湿口联动：主机只在确认烘干硬件运行后延时控制排湿口打开；手动烘干的
  温度和持续时间由 ACE2 `DRYING` 原生状态机执行，倒计时结束由 ACE2 停止加热和风扇。
  自动烘干仍按湿度条件控制任务。
- 根据 `ace2-pro.proto`，ACE2 的 `StatusResponse` 未提供排湿阀状态字段，协议也没有
  GET_VALVE_STATUS 命令，因此当前状态显示采用 `SET_VALVE` 成功回执；所有烘干联动
  阀门动作延迟 10 秒执行，以避开 ACE2 固件自身的开合脉冲。
- 排湿口按钮状态以当前窗口最近一次成功发送的打开/关闭命令为准：打开命令成功后打开
  按钮立即橘色呼吸、关闭按钮停止呼吸；关闭命令成功后反向显示。后台刷新不会用缺失的
  阀位字段覆盖该本地状态；ACE2 重启后再以设备返回值作为初始状态。
- 手动烘干与自动烘干现在使用独立运行状态；手动排湿按钮为立即执行的独立用户控制，
  不再被烘干任务的状态联动或延迟队列阻塞。
- 设置页在默认烘干时长下新增“烘干中自动打开排湿口延时时间”。范围为 `0–9999` 秒，默认
  `10` 秒；`0` 关闭烘干任务的自动排湿。仅在手动/自动烘干已确认加热器和风扇运行后开始计时，
  不影响用户手动打开或关闭排湿口。
- 排湿口状态显示不再采用 ACE2 启动烘干时自行产生的一次开合脉冲；仅在 multiACE 延时打开
  命令收到成功回执后显示“已打开”。手动或自动烘干停止会取消待执行的打开命令并立即显示关闭。
- 明确手动烘干参数语义：温度是 ACE2 加热器的 PID 目标温度，用于达到并稳定在设定温度；
  时长（分钟）才是关闭倒计时。手动任务不会因温度达到目标而停止，也不会把温度当作开关阈值。
- 修复自动湿度定时器误发送 `drying_stop` 停止手动烘干的问题；手动任务运行期间自动控制器
  不再接管同一 ACE，手动烘干仅由用户停止或设定时长结束。
- 手动和自动烘干的温湿度控制周期统一为 5 秒；底层 ACE2 心跳仍保持约 1 秒，用于及时接收
  设备状态，避免降低页面状态刷新速度。
## 1.0 热修复：ACE 长时间烘干断连与 Web 延迟

- 修复 `ACE_REPAIR_HEAD_SOURCE` 保存材料来源时，颜色、品牌或其他特殊字符破坏 `SAVE_VARIABLE` 字面量并触发 Klipper `Internal error on command:"SAVE_VARIABLE"` 的问题。头部来源现在以带 `b64:` 前缀的 UTF-8 Base64 字符串持久化，同时兼容旧版字典格式。
- 修复 Fluidd 与 multiACE 页面重复提交 `ACE_SWITCH + MULTIACE_REFRESH_OVERRIDES` 的问题。后端对批次加锁并在 2 秒内合并完全相同的请求，避免 G-code 队列堆积、`wait_ace_ready` 长时间 busy 以及 ACE 串口断连。
- 本修复不改变自动烘干温度、湿度、排湿口和打印联动规则；只修复持久化和请求调度路径。

### 原厂屏幕退料保护

- 修复原厂屏幕退料流程中发生无效 `SAVE_VARIABLE` 参数时，`SyntaxError` 未被原厂保存组件捕获并导致 Klipper SHUTDOWN 的问题。
- 现在无效保存请求只会返回普通 G-code 错误，不会关闭 Klipper；日志会保留原始参数，供后续定位发送方。
