# multiACE v0.99.2b-MakerDad0.7 更新说明

## G-code 上传与分析

- mUlt1ACE Web UI 的 G-code 预检/重写流程强制使用电脑浏览器端 Worker 执行。
- 打印机端只提供当前 ACE/料槽状态和 Python 规则源码，不再接收原始 G-code 做分析。
- 处理完成后，仅将重写后的最终 G-code 通过 Moonraker 上传到打印机并开始打印。
- 删除 Web UI 中“浏览器失败后转用打印机端预检”的回退入口。
- 移除打印机端 `/api/preflight` 原有 110 MB 大小限制，保留接口仅作兼容，不作为 Web UI 正常路径。
- 增加本地进度阶段显示：电脑端加载分析运行时、初始化 Python、装载分析规则、读取 G-code、分析、重写、上传。
- 对大文件读取改为浏览器端流式读取并回传进度，避免长时间停在“已排队 - 0%”。
- 页面加载后预热浏览器端 Worker，减少第一次上传时等待运行时初始化的时间。

## 说明

- 真实计算位置：PC 浏览器 Web Worker。
- 打印机端工作：提供实时料槽状态、提供规则源码、接收处理后的 G-code。
- 剩余限制来自浏览器内存/PC 性能、Pyodide 运行时加载能力，以及 Moonraker/nginx 全局上传限制。

## 保持不变

- 保留准许打印温度保护。
- 保留自动烘干独立启动按钮和手动停止后必须再次启动的逻辑。
- 保留 v0.99.2b-MakerDad0.6 中恢复的默认连线显示方式。

已完成 JavaScript、Python、JSON 语法检查及两套固件 overlay 一致性检查。
